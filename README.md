# Техникалық тапсырма (ТЗ)
## KT Neural Document Agent (Нейрондық Құжат Талдау Агенті)

---

## 1. Жалпы ережелер
* **Жобаның мақсаты:** Ұйымды қайта құрылымдау (реорганизация) кезінде ішкі нормативтік құжаттардың (Ережелер, Нұсқаулықтар т.б.) екі редакциясын («дейін» және «кейін») семантикалық әрі функционалдық тұрғыдан автоматизацияланған салыстыру[cite: 1].
* **Негізгі міндеті:** Функциялардың жоғалуын, қайталануын, жаңадан пайда болуын, мүдделер қақтығысын анықтау және әрбір тұжырымды құжаттың нақты тармағына байланыстыру (Explainable AI / Source Trace)[cite: 1].

---

## 2. Жүйе архитектурасы мен құрамы

Жүйе 3 негізгі модульден тұрады[cite: 1]:

1. **Frontend (Frontend/UI):**
   * **Технологиялар:** Single Page Application (HTML5, CSS3, Vanilla JS) / Streamlit (MVP үшін)[cite: 1].
   * **Интерфейс компоненттері:**
     * *Neural Core:* Анимациялық өңдеу орталығы[cite: 1].
     * *Document A/B View:* Екі құжатты қатар салыстыру аймағы[cite: 1].
     * *Source Trace & Agent Insight:* Агенттің қорытындысы мен нақты тармақтарға сілтеме беретін модуль[cite: 1].
     * *Command Line (Ctrl+K):* Жедел командалар жүргізу диалогы[cite: 1].

2. **Backend (API Server):**
   * **Технологиялар:** Node.js (REST API) немесе Python (FastAPI / Streamlit)[cite: 1].
   * **API Эндпоинттері:**
     * `POST /api/documents` — Файлдарды жүктеу және валидациялау[cite: 1].
     * `POST /api/analyze` — Құжаттарға семантикалық анализ жүргізу сұрауын жіберу[cite: 1].
     * `POST /api/agent` — Агентке еркін интерактивті сұрақ қою[cite: 1].
     * `GET /api/evidence/:id` — Нақты дәлелдемелер мен тармақтарды алу[cite: 1].

3. **Core Processing & AI Engine (Парсинг және ЖИ ядросы):**
   * **Parser (`core/parser.py`):** `.pdf`, `.docx`, `.xlsx`, `.txt` форматтарынан мәтінді оның тармақтық нумерациясын (1.1, 2.3 т.б.) сақтай отырып алу[cite: 1].
   * **Analyzer (`core/analyzer.py`):** Anthropic Claude API / OpenAI API интеграциясы. Арнайы жүйелік промпт арқылы құрылымдалған JSON жауабын алу[cite: 1].

## 3. Функционалдық талаптар

Жүйе төмендегі функцияларды орындауға міндетті[cite: 1]:

1. **Файлдарды өңдеу:**
   * Сүйреп апару (Drag-and-Drop) арқылы PDF, DOCX, XLSX файлдарын қабылдау[cite: 1].
   * Файл көлемін тексеру (максимум 20 MB) және форматты клиент тарапынан да, серверде де валидациялау[cite: 1].

2. **Құрылымдық және семантикалық талдау (AI Analyzer):**
   * **Құрылымдық өзгерістер:** Жаңадан құрылған, сақталған, жойылған немесе біріктірілген департаменттер мен бөлімшелерді анықтау[cite: 1].
   * **Функцияларды сәйкестендіру:** Қайта тұжырымдалған функцияларды бір-бірімен сәйкестендіру (Matrix Mapping)[cite: 1].
   * **Қауіптерді анықтау:**
     * *Lost Functions:* Басқа бөлімге берілмей, мүлдем жоғалған функциялар[cite: 1].
     * *Overlaps / Conflict of Interest:* Екі немесе одан да көп бөлімге бірдей функцияның жүктелуі немесе бақылаушы мен орындаушы функцияларының қайталануы[cite: 1].

3. **Дереккөзді бақылау (Source Trace / Explainability):**
   * Агент шығарған әрбір қорытынды үшін «A құжаты, X тармағы» ↔ «B құжаты, Y тармағы» түріндегі дәлелді сілтемелерді ұсыну[cite: 1].

4. **Экспорттау және Есептілік:**
   * Талдау нәтижелерін JSON, CSV және PDF (басып шығаруға бейімделген) форматтарында экспорттау мүмкіндігі[cite: 1].

## 4. Функционалды емес талаптар

1. **Қауіпсіздік және деректер құпиялылығы:**
   * Frontend бөлігінде API кілттерін сақтауға қатаң тыйым салынады[cite: 1].
   * Сессия күйі (Session State) уақытша жадта сақталады[cite: 1].
   * CSV файлдарын экспорттау кезінде формула инъекцияларынан қорғау (Formula Prefix Protection)[cite: 1].

2. **Өнімділік:**
   * Сыртқы ЖИ сұрауларының ең жоғары таймауты (Timeout) — 120 секунд[cite: 1].
   * Жауап беру уақыты созылған жағдайда талдауды тоқтату батырмасы (Abort Controller) болуы тиіс[cite: 1].

3. **Интерфейс (UI/UX):**
   * Адаптивті дизайн (Desktop/Mobile)[cite: 1].
   * Жүйелік қаріптерге және оффлайн режиміне қолдау көрсету[cite: 1].

## 5. Қабылдау тестінің сценарийі (Acceptance Criteria)

Жүйенің дайындығын тексеру үшін төмендегі критерийлер қолданылады[cite: 1]:
1. Екі түрлі редакциядағы құжат (мысалы: №8 және №9 редакциялары) жүктелгенде[cite: 1]:
   * Жүйе жаңадан құрылған құрылымдарды (мысалы: ДИТААД, ДОА) жүйелі түрде көрсете алуы керек[cite: 1].
   * Ескі және жаңа тармақтарды (мысалы, 3.4, 3.5, 5.3.2) қатар ашып, семантикалық айырмашылықты көрсете алуы қажет[cite: 1].
2. Талдау аяқталған соң сараптамалық есеп PDF/CSV форматында дұрыс жүктелуі тиіс[cite: 1].
